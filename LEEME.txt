FOODTRACK PRO — VERSIÓN 4.0 INTEGRAL
====================================

Esta versión amplía el proyecto existente. Está pensada para actualizar la instalación actual, no para reemplazarla por una base de datos nueva.

FUNCIONES INCLUIDAS
-------------------
1. Catálogo y negocios
- Solamente el administrador puede crear nuevos negocios y asignarles un dueño.
- El dueño puede modificar los datos de su negocio, teléfono, WhatsApp, dirección, imagen/flyer, platos, precios y disponibilidad.
- Horario semanal de lunes a domingo, con varios intervalos por día. Ejemplo: 08:00-12:00, 14:00-22:00.
- Los negocios cerrados por horario se omiten del catálogo normal, pero pueden aparecer cuando el cliente busca su nombre o comida; se muestra el próximo horario disponible.
- Los negocios bloqueados, suspendidos, desactivados o sin dueño asignado no aparecen al cliente.

2. Pedidos y entrega
- Se puede elegir pedido lo antes posible o una hora futura para que esté listo.
- El servidor exige al menos 15 minutos de antelación y comprueba el horario del negocio y el tiempo de preparación.
- La hora solicitada se guarda como hora en que el pedido debe estar listo/para recoger. La hora estimada de entrega a domicilio añade por separado los minutos de trayecto.
- El servidor comprueba los productos, opciones, disponibilidad, cantidades y precios del menú antes de guardar el pedido.
- El dueño recibe eventos de pedidos nuevos, incluso programados. El cliente recibe avisos cuando el pedido es aceptado, está listo, se cancela, un repartidor lo acepta y se entrega.
- El repartidor acepta pedidos listos mediante una operación transaccional del servidor y confirma la entrega; la asignación y los estados se guardan en PostgreSQL.
- El cliente puede ocultar su historial de su propia vista. No se eliminan los pedidos ni los registros financieros/históricos.

3. Suscripciones y pagos de negocios
- El administrador configura un plan, cuota, fecha de alta y fecha de vencimiento por negocio.
- El administrador registra manualmente los pagos y la fecha hasta la que cubren.
- El negocio pasa a período de gracia al vencer. Se suspende cuando han transcurrido 7 días completos de gracia sin pago registrado.
- Registrar un pago con cobertura vigente reactiva el negocio.
- La facturación de esta versión es un registro administrativo manual; no es una pasarela de pago ni procesa cobros automáticamente.

4. Alertas y PWA
- Se puede seleccionar entre varios tonos y probar el sonido desde el panel del dueño.
- Se usa vibración cuando el navegador/dispositivo la admite. El volumen final depende del dispositivo y del sistema operativo.
- Web Push funciona solo después de configurar VAPID en Render, conceder permiso y activar las alertas en cada dispositivo/cuenta.
- La aplicación conserva manifest y Service Worker para instalación como PWA. El contenido estático puede quedar en caché, pero los pedidos y operaciones necesitan conexión a Internet.

5. Idiomas
- Selector de español, inglés y francés; el idioma elegido se conserva en ese dispositivo.
- Se traducen los principales textos de la interfaz. Algunos mensajes técnicos o textos secundarios pueden seguir apareciendo en español; no se debe considerar una traducción exhaustiva al 100%.

DATOS Y MIGRACIONES
-------------------
- Se mantiene el modelo actual de pedidos y catálogo guardados en `app_state` de PostgreSQL.
- Se añaden columnas a `app_users` y tablas independientes `restaurant_billing` y `restaurant_payments`.
- Las migraciones se ejecutan al iniciar el servidor con `CREATE TABLE IF NOT EXISTS` y `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`.
- No se incluye ninguna orden para borrar tablas, reiniciar `app_state` o crear una base nueva.
- El historial que un cliente oculta sigue guardado en la base de datos.
- Negocios antiguos que no tenían horario semanal se muestran inicialmente como disponibles; al abrir su formulario de edición, se precarga un horario diario amplio para evitar cerrarlos accidentalmente. El dueño debe sustituirlo por sus horas reales. Los negocios nuevos quedan cerrados por horario hasta configurar al menos un intervalo.

LIMITACIONES QUE DEBES CONOCER
------------------------------
- El bloqueo automático por suscripción se recalcula en solicitudes API (por ejemplo, al cargar el estado o consultar facturación). No hay un proceso cron independiente que se ejecute si el servidor no recibe solicitudes.
- El registro de pagos es manual y no se conecta a un banco, Stripe ni Verifone.
- Las traducciones cubren los textos principales, no cada mensaje del sistema.
- El sonido personalizado se reproduce cuando la página está abierta y el navegador permite audio. Las notificaciones Push pueden llegar en segundo plano si el navegador/dispositivo lo admite y se ha autorizado.
- La vibración no está disponible en todos los navegadores o equipos.
- La hora se interpreta con la zona IANA definida en `BUSINESS_TIMEZONE`; si los negocios operan en Guyana Francesa, usa `America/Cayenne`.

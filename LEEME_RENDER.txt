FOODTRACK PRO 4.0 — ACTUALIZACIÓN SEGURA EN GITHUB Y RENDER
===========================================================

ANTES DE CAMBIAR CÓDIGO
-----------------------
1. En Render, abre el servicio PostgreSQL que ya utiliza FoodTrack Pro y crea/descarga una copia de seguridad (backup/export) antes de desplegar.
2. Comprueba que el servicio web `foodtrack-pro` continúa conectado a la misma base de datos.
3. NO borres la base de datos. NO cambies ni regeneres `DATABASE_URL` ni `JWT_SECRET`.
4. No pulses “Apply Blueprint” ni sincronices el Blueprint de `render.yaml` a ciegas: ese archivo describe recursos y un secreto generable y podría intentar crear/reemplazar recursos o variables. Para esta actualización solo hace falta desplegar el código en el servicio existente.

COPIAR EL PROYECTO
------------------
1. Descarga y descomprime `FoodTrack_Pro_v4_Integral.zip`.
2. Abre la carpeta interior `foodtrack`.
3. Copia el CONTENIDO de esa carpeta (server.js, index.html, package.json, sw.js, manifest.json, iconos y documentos) directamente a la carpeta raíz de tu repositorio local existente. No crees otra carpeta `foodtrack` dentro de la raíz por error.
4. Conserva la carpeta oculta `.git` de tu repositorio local. El ZIP no incluye `.git`, precisamente para que no sobrescribas el repositorio que ya tienes.
5. No copies ningún archivo `.env` ni claves privadas al repositorio. Esta entrega no necesita que compartas tus secretos.

SUBIR A GITHUB DESDE POWERSHELL
-------------------------------
Abre PowerShell dentro de la carpeta raíz local del repositorio (la que contiene `.git`) y ejecuta: 

  git status
  git add .
  git commit -m "FoodTrack Pro v4 actualización integral"
  git push origin main

Si `git status` indica que no hay cambios, comprueba que copiaste los archivos en la carpeta correcta. Si tu rama principal no se llama `main`, usa el nombre que muestre `git branch --show-current`.

DESPLIEGUE EN RENDER
--------------------
1. Render detectará el nuevo commit y desplegará el servicio web existente.
2. Espera a que el despliegue termine y el servicio aparezca como Live.
3. Abre `https://TU-DOMINIO/api/health`. Debe responder con `ok: true` y `database: connected`.
4. Si el deploy falla, no elimines la base de datos ni cambies `DATABASE_URL`/`JWT_SECRET`. Revisa los logs de Render y comparte una captura donde no aparezcan secretos.

VARIABLES DE ENTORNO EN EL SERVICIO EXISTENTE
----------------------------------------------
- Mantén intactas `DATABASE_URL` y `JWT_SECRET`.
- Mantén las variables `WEB_PUSH_PUBLIC_KEY`, `WEB_PUSH_PRIVATE_KEY` y `WEB_PUSH_SUBJECT` que ya hayas configurado. No pegues la clave privada en GitHub ni en el chat.
- Comprueba `BUSINESS_TIMEZONE`. Si tus negocios operan en Guyana Francesa, el valor debe ser `America/Cayenne`. Si están en otro territorio, usa su nombre de zona horaria IANA correcto. Cambia solamente esta variable desde Environment del servicio web; no apliques el Blueprint completo.
- Conserva también `ADMIN_USERNAME`, `ADMIN_PHONE` y `ADMIN_PASSWORD` actuales.

DESPUÉS DEL DESPLIEGUE
----------------------
1. Entra como administrador y comprueba que aparecen los negocios actuales.
2. Edita un negocio antiguo y reemplaza el horario amplio precargado por sus horarios reales. Los negocios nuevos no aparecerán a los clientes hasta que se les asigne un dueño y tengan al menos un intervalo de apertura.
3. En “Suscripciones y pagos de restaurantes”, configura el plan, cuota, fecha de alta y vencimiento de cada negocio. Los negocios sin plan configurado no tienen vencimiento automático.
4. Activa las notificaciones en el dispositivo del dueño y en el del cliente usando el botón “Activar avisos”; concede el permiso del navegador y prueba el sonido desde el panel del dueño.
5. Prueba un pedido inmediato, uno programado con más de 15 minutos, aceptación, pedido listo, asignación del repartidor y entrega completada.
6. Prueba la función “Ocultar mi historial” con una cuenta de cliente de prueba y confirma que los pedidos siguen apareciendo en los informes administrativos del negocio.

ZONA HORARIA Y PEDIDOS PROGRAMADOS
----------------------------------
La variable `BUSINESS_TIMEZONE` determina los días y horas de apertura y el cálculo de vencimientos de suscripciones. La hora programada que el cliente introduce significa “pedido listo / disponible para recoger”; la estimación a domicilio agrega el tiempo de trayecto. Prueba las horas con una cuenta y un negocio de la misma zona horaria.

IMPORTANTE
----------
Este ZIP contiene código preparado; no está desplegado en Render ni subido a GitHub por esta herramienta. Debes copiarlo a tu repositorio y realizar el push para iniciar el despliegue del servicio existente.
